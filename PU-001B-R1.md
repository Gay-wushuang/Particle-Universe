## 2. Historical potential equivalence

Command:

```text
python -m unittest discover -s tests -v
```

The test obtains the old implementation directly with:

```text
git show ed4faad4bd571f2a5ba8c7fabe2a45961792d326:particle_universe/potential.py
```

It dynamically loads that source alongside the current vectorized class. CI
checkout was changed to `fetch-depth: 0` so the historical object is available;
no hand-written force implementation is used as the sole reference.

Coverage includes nine two-body distances (`r<rc`, the LJ minimum, the nearest
float below `rc`, exact `rc`, the nearest float above it, and `r>rc`), four
deterministic asymmetric random configurations, a 108-particle FCC state, an
explicit PBC minimum-image case, and direct plus periodic-image overlaps.
Potential energy, every force component, interacting-pair count, net force,
scalar pair force, cutoff semantics, and rejection behavior are checked.

The predeclared mixed tolerance is `atol=5e-12`, `rtol=5e-14`. The absolute
term protects comparisons near zero; the relative term permits float64
summation-order roundoff for large forces. Across 15 numeric configurations:

- maximum absolute energy difference: `4.661160346586257e-12`;
- maximum absolute force-component difference: `8.149072527885437e-10`;
- maximum new-implementation total-force norm: `3.336437816093669e-14`;
- all pair counts matched and all mixed-tolerance comparisons passed;
- exact `r=rc` produced zero force and zero shifted energy in both versions;
- both implementations rejected direct and periodic-image overlaps.

The largest absolute force difference belongs to a deliberately close PBC
pair with a very large force magnitude and satisfies the relative tolerance.
Result: **EQUIVALENT_WITHIN_TOLERANCE**. This supports conditional retention of
the vectorization without claiming cross-commit bitwise equality.
